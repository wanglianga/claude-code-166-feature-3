# 乡镇卫生院家庭病床申请巡诊耗材医保结算平台

面向乡镇卫生院的家庭病床一体化平台：**家属申请 → 家庭医生六要素评估 → 可解释排班 → 护士上门执行（体征/压疮/换药/导尿/血糖血压/用药/家属签字）→ 医生调处方/复诊/转诊（远程复核）→ 护理+耗材+冷链统一账单（医保/自费一单清）→ 医保合规审查 → 全链可还原**。

内置**病情恶化转诊闭环**：护士巡诊发现呼吸困难等恶化 → 立即标记高危并同时通知家庭医生/家属/转诊医院 → 医生远程判断发起救护车转运（家庭病床暂停、未上门任务取消、未结算项目转待审核）→ 等待医院回传入院诊断或家属补充结果以确定费用截至时间（住院期间巡诊不计费、截至未定前禁止出账）→ 出院后医生决定恢复（计划重启并补排巡诊）或终止建床。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts；Spring Boot 3.3 + Spring Security/JWT + JPA；PostgreSQL 15；Docker Compose 一键启动。

## 一、快速启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

- 前端：http://localhost:8088
- 后端 API：http://localhost:8080
- Swagger UI（OpenAPI 3 文档）：http://localhost:8080/swagger-ui.html
- PostgreSQL：localhost:5432（homebed/homebed123）

首次启动后端会自动建表并写入演示数据（9 个测试账号、4 名患者、申请/评估/计划/已完成巡诊/医嘱/风险事件/一张含合规初审结果的演示账单，以及一张“已标记高危、待医生远程判断”的演示转诊单）。

停止：`docker compose down`（保留数据加 `-v` 之外默认保留卷；清空数据用 `docker compose down -v`）。

## 四、建议的业务验证路径

1. **家属** 登录 → “建床申请”为老人提交申请（勾选护理需求）。
2. **家庭医生** 登录 → 对申请评估：病情/距离（可按坐标自动测算）/照护人/医保资格/护理项目频次/风险等级 → 批准建床或驳回。
3. **管理者** → “巡诊计划排班”选择批准单 → **智能排班**：查看三名护士在技能匹配、本周负荷、路线聚集、半径红线上的打分，以及“为什么是她、为什么不是别人”的可解释说明与基层约束权衡（系统自动生成 4 周上门任务）。
4. **护士** → “上门巡诊”对待办任务**签到上门** → 填写体征、压疮/换药/导尿/用药记录、勾选护理收费项、领用耗材（冷链药品登记交接温度）、上传现场照片、采集**家属手写签字**后提交。
   - 可验证异常：上报“家属不在家/耗材缺货/患者住院”等，任务自动挂起；管理者在“巡诊异常”中改期/改派恢复。
   - 可验证风险：血压 ≥180/110、血氧 <92%、冷链温度越界等会**自动生成风险事件**。
5. **家庭医生** 在巡诊记录中**下达医嘱**（调整处方/复诊/转诊）→ 用 `doctor2` 登录“医嘱与远程复核”完成**另一名医生远程复核**。
6. **财务** → “统一账单”按账期生成：护理服务、耗材领用、冷链药品合并为一单，自动拆分医保报销与家属自费；同来源已出账不重复计入。
7. **家属** 打开账单逐行核对（每行可回溯到巡诊记录与出库流水）→ 确认，或点“对收费有疑问”发起**收费质疑**；财务可对照“服务全链还原”答复并剔除重算。
8. **医保经办** → “医保合规审查”：查看自动初审命中规则（R1 重复收费、R2 超频次、R3 无家属签字、R4 医保资格存疑、R5 冷链温度缺失、R6 目录变化按快照结算、R7 照片证据缺失），给出复核结论后财务结算。
9. **收费/医保目录**（财务）对目录项执行“目录变更”：旧版本失效、新版本生效，历史账单不受影响（R6 会提示按出账快照还原）。
10. **病情恶化转诊闭环**（演示数据已预置患者孙桂英“呼吸困难”高危转诊单，待医生判断）：
    1. **护士** 在“上门巡诊”对任务点“病情恶化”（或在“转诊闭环”页直接标记）→ 填写症状（默认呼吸困难）/转诊医院 → 平台立即标记高危，**同时通知家庭医生、家属、转诊医院**（站内信+短信模拟，通知记录留痕），并联动生成 HIGH 风险事件。
    2. **家庭医生** 在“转诊闭环”页收到通知 → 远程判断：**发起救护车转运**（家庭病床计划暂停、建床申请挂起、未上门任务取消、待确认账单转“转诊待审核”）或**继续居家观察**（转诊取消，服务不受影响）。
    3. 转运后**费用截至时间未定**：财务对该患者出账被阻断；待**管理者/医生登记医院回传**（入院诊断+入院时间）或**家属补充住院结果**后，费用截至入院时点，待审核账单自动释放，**住院窗口内的巡诊不计费**。
    4. **出院登记**后由**家庭医生决定**：恢复家庭病床（计划重启、申请恢复、按剩余周期自动补排巡诊）或终止建床（计划取消、申请转“转诊终止建床”）。
11. **管理者看板**：巡诊负荷与超时、上门半径分布与超半径患者、异常类型、风险分布、耗材消耗 Top 与缺货预警、金额概览。
12. **服务全链还原**：选择任一建床申请，查看申请→评估→排班→每次上门（签到/体征/照片/耗材/异常/医嘱/家属签字）→账单→合规→风险→**转诊闭环（标记/判断/入院/出院/恢复决定）**的完整时间线证据。

### 演示数据中预置的冲突素材

- 患者李长顺同一天两次换药（晚间敷料渗湿补换）：合规初审自动命中 **R1 重复收费/超每日限次**，可由医保经办结合家属签字与照片判定“情况属实准予报销”——体现系统是**可解释提示**而非机械拒付。
- 一支门冬胰岛素领用**未登记冷链温度** → 命中 **R5**；登记温度越界则自动生成冷链风险事件。
- 患者孙桂英住在大岭村山后（约 6km，超出 5km 半径）且有 HIGH 风险与待处理血氧风险，排班解释中给出“同片区拼单、雨雪改期、家属须在场”的安排理由。

## 五、实际执行过的验证（本环境）

- `mvn clean package`：后端编译打包通过（Java 17）。
- 后端连接本地 PostgreSQL 15 真实启动，JPA 自动建表、演示数据初始化成功（含统一账单自动生成与合规初审、预置“待医生判断”的呼吸困难转诊单）。
- 执行端到端冒烟脚本（13 个场景全部通过）：7 个角色登录、医生评估批准、可解释排班生成 12 次任务与候选评分、看板 KPI、护士待办、统一账单金额拆分（总额 392.00 / 医保 289.40 / 自费 102.60）、合规初审命中 R1×3+R5、家属确认、医保复核结算、服务链 20 节点时间线、护士完成上门后血压危急值自动生成 HIGH 风险、转诊医嘱经第二位医生远程复核、医保目录变更发版。
- 执行**病情恶化转诊闭环**端到端冒烟脚本（19 项断言全部通过，覆盖 4 个场景）：
  - 标记高危：护士标记“呼吸困难”→ 转诊单创建、医生/家属/转诊医院三方通知留痕、联动 HIGH 风险事件；重复标记被拒；家属/护士越权操作返回 403。
  - 救护车转运：医生远程判断后计划暂停、建床申请挂起、未上门任务取消、待确认账单转“转诊待审核”；费用截至未定前财务出账被阻断、家属不可确认待审核账单。
  - 费用截至：家属补充住院结果（入院诊断+入院时间）→ 费用截至入院时点、待审核账单自动释放；费用截至后住院窗口内的巡诊提交不计费（账单总额为 0，审计日志记录“剔除转诊住院期间巡诊”）。
  - 闭环分支：出院登记→医生恢复家庭病床（计划重启+申请恢复+自动补排巡诊）；医生判断继续观察（转诊取消、服务不受影响）；医院回传→出院→终止建床（申请转“转诊终止建床”、计划取消）；服务全链还原时间线含转诊标记/判断/入院/出院/恢复决定节点；家属收到结果通知并可已读。
- `npm run build`：前端生产构建通过；`npm run dev` 启动后验证页面可访问且经 Vite 代理登录后端成功（含新增“转诊闭环”页面路由）。
- Docker：已提供多阶段 Dockerfile 与 docker-compose.yml（当前沙箱无 docker 守护进程，未在本机执行镜像构建；部署环境执行 `docker compose up -d --build` 即可）。
