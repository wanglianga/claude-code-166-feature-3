# 乡镇卫生院家庭病床申请巡诊耗材医保结算平台

面向乡镇卫生院的家庭病床一体化平台：**家属申请 → 家庭医生六要素评估 → 可解释排班 → 护士上门执行（体征/压疮/换药/导尿/血糖血压/用药/家属签字）→ 医生调处方/复诊/转诊（远程复核）→ 护理+耗材+冷链统一账单（医保/自费一单清）→ 医保合规审查 → 全链可还原**；并内置**病情恶化转诊闭环**：护士巡诊发现呼吸困难等高危表现 → 立即标记高危并通知家庭医生/家属/转诊医院 → 医生远程判断发起救护车转运 → 家庭病床与巡诊计划暂停、后续排班取消、未结算账单进入待审核 → 等待医院回传或家属补充入院诊断 → 按“救护车出发/实际入院较早者”核定家庭病床费用截至时间（住院后不再计费）→ 出院后由医生决定恢复家庭病床或撤床。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts；Spring Boot 3.3 + Spring Security/JWT + JPA；PostgreSQL 15；Docker Compose 一键启动。

## 一、快速启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

- 前端：http://localhost:8088
- 后端 API：http://localhost:8080
- Swagger UI（OpenAPI 3 文档）：http://localhost:8080/swagger-ui.html
- PostgreSQL：localhost:5432（homebed/homebed123）

首次启动后端会自动建表并写入演示数据（9 个测试账号、4 名患者、申请/评估/计划/已完成巡诊/医嘱/风险事件/一张含合规初审结果的演示账单）。

停止：`docker compose down`（保留数据加 `-v` 之外默认保留卷；清空数据用 `docker compose down -v`）。

## 四、建议的业务验证路径

1. **家属** 登录 → “建床申请”为老人提交申请（勾选护理需求）。
2. **家庭医生** 登录 → 对申请评估：病情/距离（可按坐标自动测算）/照护人/医保资格/护理项目频次/风险等级 → 批准建床或驳回。
3. **管理者** → “巡诊计划排班”选择批准单 → **智能排班**：查看三名护士在技能匹配、本周负荷、路线聚集、半径红线上的打分，以及“为什么是她、为什么不是别人”的可解释说明与基层约束权衡（系统自动生成 4 周上门任务）。
4. **护士** → “上门巡诊”对待办任务**签到上门** → 填写体征、压疮/换药/导尿/用药记录、勾选护理收费项、领用耗材（冷链药品登记交接温度）、上传现场照片、采集**家属手写签字**后提交。
   - 可验证异常：上报“家属不在家/耗材缺货/患者住院”等，任务自动挂起；管理者在“巡诊异常”中改期/改派恢复。
   - 可验证风险：血压 ≥180/110、血氧 <92%、冷链温度越界等会**自动生成风险事件**。
5. **家庭医生** 在巡诊记录中**下达医嘱**（调整处方/复诊/转诊）→ 用 `doctor2` 登录“医嘱与远程复核”完成**另一名医生远程复核**。
6. **财务** → “统一账单”按账期生成：护理服务、耗材领用、冷链药品合并为一单，自动拆分医保报销与家属自费；同来源已出账不重复计入。
7. **家属** 打开账单逐行核对（每行可回溯到巡诊记录与出库流水）→ 确认，或点“对收费有疑问”发起**收费质疑**；财务可对照“服务全链还原”答复并剔除重算。
8. **医保经办** → “医保合规审查”：查看自动初审命中规则（R1 重复收费、R2 超频次、R3 无家属签字、R4 医保资格存疑、R5 冷链温度缺失、R6 目录变化按快照结算、R7 照片证据缺失），给出复核结论后财务结算。
9. **收费/医保目录**（财务）对目录项执行“目录变更”：旧版本失效、新版本生效，历史账单不受影响（R6 会提示按出账快照还原）。
10. **管理者看板**：巡诊负荷与超时、上门半径分布与超半径患者、异常类型、风险分布、耗材消耗 Top 与缺货预警、金额概览。
11. **服务全链还原**：选择任一建床申请，查看申请→评估→排班→每次上门（签到/体征/照片/耗材/异常/医嘱/家属签字）→账单→合规→风险的完整时间线证据。

### 病情恶化转诊闭环（独立菜单“转诊闭环”，亦可从风险事件/上门巡诊进入）

预置场景：患者 **孙桂英（慢阻肺，大岭村，建床号 JC-0003）** 今日巡诊时被 `nurse3` 发现突发呼吸困难、指脉氧 88%，演示数据已推进到「转诊完成·待回传诊断」，可直接从后半段验证；也可对其他患者从头走完整流程。

1. **护士/医生** 在“转诊闭环”点 **标记高危转诊**（选择患者与现场巡诊任务，填写呼吸困难等表现）→ 系统立即：
   - 生成高危风险事件、挂起当前巡诊任务（病情恶化异常）；
   - 向 **家庭医生、家属、转诊医院** 三方推送通知（站内+短信/语音/区域转诊平台，页面“三方通知留痕”可查）。
2. **家庭医生**（`doctor`，或 `admin`）打开转诊单 **远程判断**：
   - **发起救护车**：家庭病床申请置为「暂停建床」、执行中巡诊计划「已暂停」、后续待上门任务自动「已取消」、**未结算账单进入“转诊待审核”冻结**，并通知家属与医院；
   - 也可选择“暂不转运·就地处置”留观。
3. 确认 **已送达医院** → 状态「转诊完成·待回传诊断」。
4. **医院回传**（任意非家属角色，模拟医院平台）或 **家属补充**（`family`）提交 **入院诊断与实际入院时间** → 系统取「救护车出发时间」与「实际入院时间」的**较早者**确定**家庭病床费用截至时间**。
5. 住院期间财务 **无法出账**（接口明确拦截）；新账单只计入截至日前的服务；被冻结的待审核账单按费用截至自动**剔除并清零住院后明细、重算金额**，由 **财务/医保审核放行**后退回家属确认。
6. **登记出院** → 家庭医生决定 **恢复家庭病床**（计划恢复、给出首次上门日、账单解冻）或 **撤床闭环**（申请置「已撤床」、计划取消）。风险事件同步闭环。
7. 在“统一账单”可见冻结/待审核与剔除行数；在“服务全链还原”可见转诊各阶段（高危/救护车/送达/诊断费用截止/出院决定）进入时间线证据。

### 演示数据中预置的冲突素材

- 患者李长顺同一天两次换药（晚间敷料渗湿补换）：合规初审自动命中 **R1 重复收费/超每日限次**，可由医保经办结合家属签字与照片判定“情况属实准予报销”——体现系统是**可解释提示**而非机械拒付。
- 一支门冬胰岛素领用**未登记冷链温度** → 命中 **R5**；登记温度越界则自动生成冷链风险事件。
- 患者孙桂英住在大岭村山后（约 6km，超出 5km 半径）且有 HIGH 风险与待处理血氧风险，排班解释中给出“同片区拼单、雨雪改期、家属须在场”的安排理由。

## 五、实际执行过的验证（本环境）

- `mvn compile` / 历史 `mvn clean package`：后端编译打包通过（Java 17）。
- 后端连接本地临时 PostgreSQL 15 真实启动（空库），JPA 自动建表、演示数据初始化成功，含转诊闭环演示数据（标记高危→三方通知→救护车→暂停计划/取消后续巡诊→冻结待审核账单→送达待诊断）。
- 转诊闭环端到端接口验证（curl 真实调用，全部符合预期）：
  - 护士标记高危后，转诊单生成 HIGH 风险事件、当前巡诊挂起，家庭医生/家属/转诊医院三条通知落库（`notifySnapshot` 可见三方送达）；
  - 家庭医生发起救护车：建床申请 `APPROVED→SUSPENDED`、计划 `ACTIVE→PAUSED`、未来两次待上门 `SCHEDULED→CANCELLED`、转诊前账单 `DRAFT→PENDING_REVIEW`；
  - 住院期间财务出账被 **400 拦截**（提示诊断与费用截至未核定）；家属以 `FAMILY_SUPPLEMENT` 提交入院诊断，费用截至取「救护车出发/实际入院较早者」（2026-10-05 10:10）；
  - 人为插入一条费用截至日（10-08）之后完成的巡诊，对 10-06~10-10 账期出账被 **拦截**，证明住院后巡诊不会继续计费；
  - 出院→医生恢复：计划恢复 `ACTIVE`、申请回 `APPROVED`、待审核账单解冻回 `DRAFT` 且保留费用截至；财务可对待审核账单审核放行；
  - 权限：家属发起救护车被 403、家属不能冒充“医院回传”、同一患者存在进行中转诊单时重复标记被 400 拦截；家属仅可见本人绑定患者的转诊单；
  - 看板 KPI 新增 `inHospitalReferrals`；服务全链时间线包含高危/救护车/送达/诊断费用截止节点；OpenAPI `/v3/api-docs` 暴露 11 个 `/api/referrals` 接口。
- `npm run build`：前端生产构建通过（Vite）。
- Docker：已提供多阶段 Dockerfile 与 docker-compose.yml（当前沙箱无 docker 守护进程，未在本机执行镜像构建；部署环境执行 `docker compose up -d --build` 即可）。
